Fixed Orange Pi 3B v1.1 · RK3566 · YT8531 PHY DietPi · kernel 6.18.54 mainline 2026-11-08

eth0 runs at gigabit again, and it survives reboots

The question: why did eth0 only work at 100 Mbit/s on DietPi when it ran at 1 Gbit/s on the vendor OS? The answer: mainline Linux never told the Ethernet chip to output its 125 MHz clock, and it left the Ethernet pins driven too weakly. RGMII timing delays, the usual suspect, were never the problem.

How it works: what was missing in the chain

The SoC's Ethernet controller (MAC) sends data over a 12-wire bus called RGMII to a separate Ethernet chip (PHY, here a Motorcomm YT8531), which puts the signal on the cable. Receiving worked fine at 1G; sending (TX) was dead. Two things on the sending side were wrong. The green dashed boxes mark the fixes.

How I found it: each experiment changed one thing

Each test ran live at 1G without rebooting, using tools/ytmii.py that reads and writes the PHY's registers directly. A test counted as passing only if unicast replies came back from the router.

Caveats

dietpi-config can undo parts of this. "Ethernet force speed" re-creates a 100M unit, and dietpi-network regenerates interfaces.d/eth0.conf. If it drops allow-hotplug eth0, the watchdog brings eth0 up about 30 s after boot.
Tested on one board (v1.1) with one kernel (6.18.54). The v2.1 board uses a different DTB, and this fix is untested there.
